# Планирование закупок

Python рассчитывает рекомендации по данным о продажах, остатках и поставках. Статичный дашборд показывает план закупок, риски и пояснения, а Excel содержит строки к заказу.

## Локальный просмотр

```sh
uv sync
uv run purchasing facts
uv run purchasing dashboard
```

Расчёт читает данные из локальной папки `share/`. Если `out/facts.json` уже готов, достаточно последней команды. Она собирает `out/dashboard/index.html` и `out/dashboard/order.xlsx` с шаблонными пояснениями без обращения к DeepSeek. Откройте `index.html` в браузере и скачайте Excel со страницы.

```sh
uv run playwright install chromium
uv run pytest
```

Для проверки в установленном Google Chrome используйте `PLAYWRIGHT_CHROMIUM_CHANNEL=chrome uv run pytest tests/dashboard`.

## Безопасность

Что куда уходит и почему:

| Что | Куда | Почему так |
|---|---|---|
| Исходные CSV | Закрытый репозиторий `purchase-planning-data`. В открытый репозиторий, в логи и в артефакты Actions не попадают | Это данные заказчика. От git их защищают `.gitignore`, pre-commit, gitleaks и автотест |
| Доступ к данным | Deploy key (ключ доступа к одному репозиторию) только на чтение, лежит в секрете `DATA_REPO_DEPLOY_KEY` | Пересчёт может читать данные, но не может их менять |
| Запрос к DeepSeek | Только белый список полей: код товара, категория, остаток, в пути, продажи, прогноз, даты, флаги риска. Без названий, поставщиков, брендов, веса и денег | ИИ только выбирает готовые фразы, числа считает Python, каждое число в тексте проверяется |
| Журнал запросов к DeepSeek | Закрытая папка `out/ai-private/` на машине запуска, не в git | Нужен для разбора спорных ответов, наружу не выходит |
| Дашборд и Excel | Публичная страница GitHub Pages | В тестовом задании там только обезличенные коды и расчётные показатели |
| Сводка | Telegram-бот, только в заданный чат (`TELEGRAM_CHAT_ID`), бот ничего не принимает | Нужна ссылка и краткая картина без выгрузки данных |
| Ключи | Секреты GitHub (`DEEPSEEK_API_KEY`, `DASHBOARD_NV_BOT`, `TELEGRAM_CHAT_ID`, `DATA_REPO_DEPLOY_KEY`) и локальный `.env` | Ни в коде, ни в тестах, ни в логах ключей нет |

Секреты читает только workflow «Пересчёт закупок», и только на ветке `main` (по расписанию или кнопкой владельца). Версии Actions закреплены по хешу, `pull_request_target` не используется, права минимальные. Подробности и известные ограничения: `docs/security.md`.

**Для реальной компании** публичную страницу нужно закрыть: вход по почте, например через Cloudflare Access.

## Данные

Для демонстрации предусмотрены обезличенные коды товаров и расчётные показатели. CSV и полный `facts.json` хранятся локально. Для реальных данных компании потребуется доступ по почте, например через Cloudflare Access.
