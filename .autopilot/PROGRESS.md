## Сессия 5 из 10 — этап 4 «Расчёт закупки» (2026-11-04): закрыт после правки плеча, все 6 проверок зелёные

Главная сессия не приняла первую версию: плечо поставки было занижено. Что нашли и поправили:
- **12 дней у grain_mills.** Плечо бралось как «первый приход товара после даты заказа», а приходы не вычитались из заказов. Приходы по старым заказам засчитывались новым (пример: заказ PO-E96669 с планом 270 дней получал приходы 2023-10…2024-06; два заказа 12.03.2025 получили по 500 шт. через 7 дней). У главного поставщика grain_mills (SUP-9D84EE) медиана вышла 12 при плановых 122.
- **Правило плеча (выбрано):** медиана планового `planned_lead_days` по заказам поставщика (от 3 заказов), значения ≤ 0 и > 400 отброшены; иначе медиана по категории (для `supply_type = unknown` сразу категория); нет и её — «нет данных». Фактическое опоздание плечо не меняет, оно только сдвигает просроченные заказы в пути. Сопоставление приходов с заказами переписано: приход делится между заказами по очереди и по количеству.
- **Распределение плеча** (блок `lead_time_distribution` в `facts.json`): по 413 товарам p25 = 101, медиана = 121, p90 = 161. README заказчика (все 660 заказов): 52 / 123 / 205. Медиана совпала; p25 выше, потому что заказы с плановым плечом ≤ 0 отброшены; p90 ниже, потому что берётся медиана по поставщику. Медиана плеча по категориям: grain_mills 122, sanitary_faucets 121, concrete_mixers 151, trimmer_blades_accessories 123, string_trimmers 103, space_heaters 256 (основной поставщик планирует 256 дней).
- **Страховой запас:** разброс спроса считается по продажам минус возвраты (раньше валовым), режим «мало истории» только при менее чем 3 месяцах от первой продажи (раньше 6). Потолок выбросов 4× медиана и потолок страхового запаса «не больше спроса за плечо + покрытие» остались.
