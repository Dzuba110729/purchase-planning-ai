## Что должно заработать

Для каждого живого товара посчитаны запас в днях с учётом заказов в пути, дата заказа, количество (кратно шагу партии), страховой запас по группе A/B/C, флаги дефицита и излишка; просроченные заказы разобраны по правилу 90 дней; итог записан в `facts.json` — единый источник цифр для всего остального.

Выполняется в сессии 5 из 10. Этап закрыт, только когда зелёные все проверки ниже; красные — чиним; не получилось — пишем в `.autopilot/PROGRESS.md` что именно и останавливаемся.

## Из брифа, дословно

> «Плечо считаем по поставщику, а не одно число 180»
>
> «Просроченные заказы — правило 90 дней. До 90 дней: в пути, дата сдвигается на обычное опоздание поставщика. Больше: не считаем, список «уточнить у поставщика».»
>
> «Период покрытия — по ритму поставщика: медиана интервала между приходами, в рамках 60–120 дней.»
>
> «Страховой запас — по ABC-группе: A — 95%, B — 90%, C — 80%. Важность = штуки × дециль цены × наценка.»
>
> «Количество округляется вверх до шага партии из истории. Нет истории — до 10 шт.»
>
> «Запас в днях с учётом заказов в пути, дата заказа, количество, флаги дефицита и излишка»

## Критерии приёмки

Проверки этапа 4. Расчёт закупки (раздел «Проверка каждого этапа», дословно):

- [ ] Автотесты на придуманных товарах с заранее известным ответом (5–6 случаев: ровный спрос, сезонный, есть заказ в пути, просроченный заказ, нулевой остаток, новый товар).
- [ ] Автотест: количество ≥ 0 и кратно шагу партии.
- [ ] Автотест: товары с наценкой < 25% и мёртвые никогда не попадают в автозакупку.
- [ ] Автотест: добавили заказ в пути на N шт. → рекомендация уменьшилась на N (или до 0).
- [ ] Автотест: дата заказа + плечо ≤ дата, когда кончится запас (иначе флаг «дефицит неизбежен»).
- [ ] Ручная: 5 товаров пересчитаны вручную в таблице, цифры совпали.
